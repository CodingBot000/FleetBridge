# Phase 1 기능 계약

## 목표와 범위
UIKit 차량 목록의 모의 차량 10대에서 Flutter 차량 상세로 이동하고 네이티브로 돌아온다. 실제 차량 제어, 서버, 지도, 인증은 범위 밖이다.

## 현재 상태
Xcode 26.6, Flutter 3.47.9, UIKit과 Storyboard 기반 앱이며 앱·단위 테스트·UI 테스트 타깃이 있다. 기본 배포 대상은 iOS 18.0이다. iOS 18.6 Simulator에서 통합 검증한다.

## 설계 및 계약
- 차량 식별자는 안정적인 문자열이며 Native 목록이 차량 데이터의 원본이다. Flutter는 선택된 차량의 데이터를 채널로 요청한다.
- 상세 진입과 닫기는 명시적인 메시지로 처리한다. 엔진의 소유자와 재사용 및 종료 시점을 구현과 함께 문서화한다.
- 잘못된 식별자, 누락 데이터와 통신 실패는 복구 가능한 오류로 표시하며 로딩 상태를 제공한다.
- Flutter 상세 상태는 Riverpod으로 관리한다. 공식 Add-to-App Swift Package Manager 통합을 우선한다.
- 최소 iOS 버전은 18.0이다. iOS 18.6 Simulator에서 검증하며 실기기 및 iOS 18.0 자체는 별도 확인한다.

## 검증 기준
- 모의 차량 10개 표시와 서로 다른 차량 연속 선택, 반복 진입 및 복귀를 검증한다.
- 잘못된 ID, 데이터 누락, 오류 및 로딩을 단위·위젯 테스트로 확인한다.
- iOS Simulator 빌드와 테스트, Flutter 테스트 및 양방향 내비게이션을 실행한다.
- 구현하지 않거나 실행하지 못한 항목은 완료로 기록하지 않는다.

## 상세 화면 생명주기
상세 진입마다 `VehicleDetailCoordinator`가 새 `FlutterEngine`과 채널을 만들고 선택 ID를 초기 라우트에 전달한다. 닫기 요청 이후 채널 핸들러를 해제하고 엔진 컨텍스트를 파괴한다. 엔진을 재사용하지 않으므로 초기 라우트와 Riverpod 컨테이너가 다른 차량의 데이터와 섞이지 않는다. Flutter는 ID를 `getVehicle`에 전달하며 Native 저장소가 결과 또는 `not_found` 오류를 반환한다. 엔진 시작 직후 핸들러가 준비되기 전 요청은 최대 20회 제한적으로 재시도하고, 그 외 오류는 자동 재시도하지 않아 사용자에게 표시한다.

패키지 산출물은 Git에 포함하지 않는다. 새 환경에서는 Flutter SDK 3.47.9를 준비한 후 `fleetbridge_detail`에서 `flutter pub get` 및 `flutter build swift-package --platform ios --no-codesign`을 실행해 `build/ios/SwiftPackages`를 생성해야 Xcode가 패키지를 찾는다. 서명 없는 산출물은 시뮬레이터 검증용이며 실기기 배포 서명은 별도로 확인해야 한다.

## 검증 상태
Xcode 26.6 / iOS 18.6 Simulator에서 전체 테스트 8개가 통과했다. 이 실행에는 잘못된 ID의 실제 MethodChannel 오류 및 복귀와 차량 1·2의 20회 왕복이 포함된다. Flutter 위젯 테스트 4개와 정적 분석도 통과했다. 별도 클론에서 초기화 스크립트와 시뮬레이터 클린 빌드를 확인했다. 메모리 누수 프로파일링과 실제 iOS 18.0 기기 검증은 수행하지 않았다.
